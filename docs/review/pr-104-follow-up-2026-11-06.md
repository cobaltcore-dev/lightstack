# PR #104 follow-up review — 2026-11-06

Reviewed the authorization and correctness changes at `e026de8`, including their failure and concurrency paths. The following additional findings are fixed on the same PR.

| Area | Reproduced failure | Fix |
|---|---|---|
| S3 credentials | Editing one's own generic credential blob changed the project returned by S3 authentication. | Authenticate against the recorded project; use the blob's tenant only for legacy rows without a project column. EC2 credential views use the same precedence. |
| S3 role revocation | A correctly signed request still returned 200 after the user's project role was removed. | Require a current project role and fail closed on role-query errors. |
| Identity self-service | Uppercase and compact UUID spellings returned 403 for the user's own profile and application credentials. | Compare parsed UUID values while preserving authorization-before-validation ordering. |
| Volume attachment | One database connection caused a timeout; concurrent attachments to different volumes collided on the device uniqueness constraint. | Lock the instance before choosing a device and use the transaction's connection for the device query. |
| Concurrent port allocation | Twelve concurrent requests through Neutron create, Nova boot allocation and Nova interface attach created eight ports holding one address. | Hold a shared subnet row lock across address selection and insertion in all three paths. |
| Dense subnets and IPv6 | A subnet with one free address falsely reported exhaustion; expanded and compressed IPv6 addresses were treated as different claims. | Complete the random search with a bounded sequential scan and canonicalize addresses. Gateway lookup errors now fail allocation. |
| Image staging | OpenStack's PUT route returned 404; an 8 MiB body caused a growing read buffer of over 2 MiB despite the upload cap. | Register PUT, stream with bounded memory, preserve 413, and prevent staging from overwriting a concurrently changed image state. |
| Image upload finalization | Injected database write failures still returned 204, sometimes leaving the image in saving. The normalized-checksum error branch substituted the original stream hash. | Atomically claim queued images, fail unsuccessful activation, require the stored checksum and reset unsuccessful uploads using a bounded cleanup context. |
| Guest network metadata | Multiple addresses on one port shared a network ID; addressless ports returned null networks; IPv6 was labeled IPv4. Routes and DNS lacked the fields consumed by cloud-init. | Unique IDs, proper IPv4/IPv6 masks, routes and DNS services, and empty arrays. |
| Flavor validation | Valid zero-disk and large flavors were rejected by arbitrary limits. | Match Flamingo's signed 32-bit bounds, positive RAM/vCPU requirements and nonnegative disk sizes. |

The metadata shape and flavor bounds were checked against OpenStack Nova's `stable/2025.2` implementations in [netutils.py](https://github.com/openstack/nova/blob/stable/2025.2/nova/virt/netutils.py) and [parameter_types.py](https://github.com/openstack/nova/blob/stable/2025.2/nova/api/validation/parameter_types.py).
