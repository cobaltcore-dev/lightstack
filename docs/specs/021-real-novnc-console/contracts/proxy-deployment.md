# Contract: console proxy deployment (SPEC-021)

The proxy is **not written by O3K**. It is the already-pinned upstream noVNC image, unmodified, with its start command overridden. This document is the contract that deployment must satisfy.

`bonigarcia/novnc:1.3.0` — already used by the verification stacks, Apache-2.0, Alpine-based.

**The tag is the image's version, not noVNC's.** It ships **noVNC 1.6.0** plus a checked-out websockify tree at `/root/noVNC/utils/websockify/`. Verified contents:

- `token_plugins.py` with `ReadOnlyTokenFile`, `TokenFile`, `TokenFileName`, `BaseTokenAPI`, `JSONTokenApi`, `JWTTokenApi`, `TokenRedis`, `UnixDomainSocketDirectory`.
- Client pages `index.html`, `vnc.html`, `vnc_lite.html`. **No `vnc_auto.html`.**
- Python 3.12 with `pip`, but **without** `requests`, `redis` or `jwcrypto` — which is why only the file-based token plugins are usable without modifying the image.

Any future image bump MUST re-verify all three: the bundled token plugins, the client page names, and the absent Python dependencies.

## The command override

The image's default entrypoint is `bash -c "/root/noVNC/utils/novnc_proxy --vnc ${VNC_SERVER}"` — a single fixed target with no token support. Replace it with websockify directly:

```sh
cd /root/noVNC/utils/websockify && \
python3 -m websockify \
  --web /root/noVNC \
  --token-plugin TokenFile \
  --token-source /var/lib/o3k/console-tokens \
  --idle-timeout 300 \
  6080
```

**`--idle-timeout` is required, not cosmetic.** It defaults to `0` (disabled), and without it an abandoned browser tab holds the guest console open indefinitely — FR-019's idle clause would be unmet.

**`--host-token` MUST NOT appear.** It makes websockify take the target host from the client instead of solely from the token, which would let a caller choose the target at connect time and defeat FR-012. It defaults off; the danger is a future addition, which is why its absence is asserted in a chart test.

**`--timeout` stays at its default `0`.** It is a hard session cap, and cutting off a legitimate long console session mid-use would be a worse defect than the one being fixed.

Expected startup output (verified):

```text
WebSocket server settings:
  - Listen on :6080
  - Web server. Web root: /root/noVNC
  - No SSL/TLS support (no cert file)
  - proxying from :6080 to targets generated by TokenFile
```

`--web` makes one component serve **both** the client page and the WebSocket relay, which is why no second container is needed.

`TokenFile` — **not** `ReadOnlyTokenFile`. See the projection contract: the read-only variant caches and would keep serving revoked tokens.

## Placement requirements

| Requirement | Why | Source |
|---|---|---|
| **`hostNetwork: true`** | The guest console binds loopback. libvirtd and its qemu processes run in the host network namespace (the chart mounts the host's libvirt socket and runs privileged), so only a host-networked pod can reach `127.0.0.1:<port>` | FR-017, FR-023c |
| **Pinned to the O3K node via required `podAffinity`** (`topologyKey: kubernetes.io/hostname`, matching the O3K pod's selector labels) | The token directory is node-local; a proxy elsewhere sees an empty directory and refuses every token. Affinity to the **pod** rather than a `nodeSelector`/`nodeName` is deliberate — it follows O3K if it is rescheduled, where a node-pinned proxy would silently read the wrong host's empty directory. Required, not preferred: a preferred rule schedules anyway and fails every token | FR-023c |
| **hostPath mount of `realMode.hostStoragePath`** | Read access to the projection | FR-023b |
| **Real mode only** | Stub mode refuses consoles at request time, so no proxy is needed or deployed | FR-027 |
| **Ships in `charts/o3k`** | Every requirement above is a property of the O3K node; putting it in the dashboard chart would pin Horizon to the hypervisor node | FR-023d |

## What chart tests must assert

Each of these has a failure mode that is silent or misleading in a live cluster, which is why they are pinned in tests rather than left to the host pass:

1. The container command is the websockify invocation above — **not** the image's default entrypoint (whose fixed `--vnc` target is the F1 bug).
2. `hostNetwork: true` is set. Without it the proxy cannot reach a loopback guest, and the symptom is "console connects then hangs".
3. Required `podAffinity` to the O3K pod with `topologyKey: kubernetes.io/hostname`. Without it, scheduling is correct only by luck on a single-node cluster.
4. The token directory is mounted, and the file mode/UID arrangement lets the proxy read it. Failure here refuses **every** token — indistinguishable from a token bug.
5. `console-tokens` is in the initContainer's list, alongside the existing five.
6. The plugin is `TokenFile`, not `ReadOnlyTokenFile`.
7. `--idle-timeout` is present with a non-zero value (FR-019 — the default of `0` disables it).
8. **`--host-token` is absent** (FR-012 — a requirement satisfied by an absent flag, so only a test can protect it).
9. The chart's own version was bumped (Article VI) — asserted against the previous release's value so the bump cannot be forgotten.
